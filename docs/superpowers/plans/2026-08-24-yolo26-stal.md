# YOLO26 STAL Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add an opt-in YOLO26-compatible STAL candidate-selection path to YOLOv13 training while preserving original GT regression targets and all inference contracts.

**Architecture:** `v8DetectionLoss` passes the detector stride list and the `stal` training option into the horizontal `TaskAlignedAssigner`. When enabled, the assigner creates a temporary centered proxy box only for `select_candidates_in_gts`; alignment metrics, conflict resolution, target generation, and box/DFL regression continue to receive the original GT tensor.

**Tech Stack:** Python, PyTorch, Ultralytics YOLOv13, pytest

## Global Constraints

- `stal` defaults to `False`; existing TAL behavior remains unchanged when disabled.
- For strides `[8, 16, 32]`, a GT dimension strictly smaller than `8` is independently replaced by `16` in the candidate-selection proxy.
- Proxy boxes must not mutate the input GT tensor.
- Padded GT rows remain excluded through `mask_gt`.
- Only horizontal `TaskAlignedAssigner` changes; `RotatedTaskAlignedAssigner` remains unchanged.
- Model YAML, Detect head, prediction, inference, ONNX, checkpoint, and DANN contracts remain unchanged.
- No new dependencies.
